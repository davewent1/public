## Knowledge Base

This is a personal knowledge archive. Use it as follows:

### Every Session

At the start of each session, load these two quick-reference files:
- `knowledge/FRAMEWORKS.md` — named mental models, frameworks, and concepts extracted from the Codex and personal reading. Alphabetized with one-line descriptions and source attribution.
- `knowledge/BENCHMARKS.md` — specific numbers, statistics, predictions, and quantified findings organized by domain.

These give you the vocabulary and evidence base to draw from in any conversation.

### When a Topic Comes Up

Consult `knowledge/TOPIC-INDEX.md` — a routing layer with topic categories (Philosophy, Identity, Technology, Relationships, Productivity, Society, Predictions, etc.). Each category points to the 1–3 most relevant source files. Read those files for deeper context before responding.

### How to Use the Knowledge

- Don't wait to be asked. If a framework or benchmark is relevant to what we're working on, surface it naturally.
- When reviewing ideas, writing, or strategy, cite specific frameworks from the knowledge base to support recommendations.
- The knowledge base shapes how you think about problems — it is not a search index. Treat it as the reading list that built this person's worldview.
- Primary source: `Codex.md` — a living document of beliefs, categorized as metabeliefs, perceptions, opinions, and predictions.
